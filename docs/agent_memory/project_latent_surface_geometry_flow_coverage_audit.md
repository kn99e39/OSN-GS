Real, user-caught divergence: Worklog 98's `build_tangent_frame_field` (`osn_gs/surface/torch_latent_surface_tangent_frame_field.py`) called `support.query_batch(points)` (Worklog 95's iterative weighted-PCA/MLS surface projection) but only kept `.normals` from the result -- `component_points = points[node_list]` used the RAW Gaussian center, never `query.positions[node_list]` (the actual projected/denoised latent-surface coordinate). This propagated unchanged through every geometry-dependent consumer in worklogs 98-102: `component.positions`, tree-integrated UV, `torch_latent_surface_edge_differential.py`'s `du`/`dv`, `torch_global_differential_uv_integration.py`'s integration target, `torch_parametric_domain_validity.py`'s fold-detection Jacobians, `torch_intrinsic_chart_atlas.py`'s chart growth, `torch_patch_identifiability.py`'s design matrix, and the final `fit_torch_visible_surface_from_uv` fit target -- meaning ALL of worklogs 99-102's "real replay" numbers and Decisions (A-D across those rounds) were measured on raw, noisy Gaussian centers, not the latent surface the whole architecture line claims to be built on.

Fix (surgical, geometry-provenance only, no estimator-behavior change): `build_tangent_frame_field` now stores `query.positions[node_list]` as `component.positions` (keeps raw points only for the existing unchanged kNN-edge-candidate/continuous-support gating, per Worklog 96's own unmodified contract). Added `raw_positions`/`projection_displacement`/`latent_supported` provenance fields to `TangentFrameFieldComponent` (default `None` for backward-compat with synthetic test fixtures). Found and fixed one more real gap: `torch_intrinsic_chart_atlas.py::_restrict_component` silently dropped these three provenance fields when building a chart-scoped view -- fixed to propagate them. Full-chain grep audit found no other raw-position substitution site among the 8 downstream consumer modules -- every one reads `component.positions` uniformly and now automatically receives correct latent geometry with zero further code changes.

New `torch_latent_surface_coverage_audit.py` + `torch_latent_surface_visualization_nurbs.py` + `scripts/devtools/latent_surface_coverage_export.py`: export the TRUE spatial coverage of what the Worklog 95 estimator produces over a full checkpoint's region-owned evidence, completely independent of any downstream acceptance gate (chart validity, identifiability, NURBS safety) -- a "latent support unit" is just a connected component of the existing continuously-supported kNN graph, no frame coherence/holonomy required; a "visualization NURBS" is attempted for every unit via a fixed resolution ladder and is NEVER hidden for being unsafe/extrapolative/underdetermined. Real 7-region export (checkpoint `baseline_compatible/final`): 7,774 raw region-owned observations, 4,599 latent-supported (59.2%), 3,175 unsupported (40.8%), 86 latent support units, 49/86 visualization NURBS materialized, projection displacement median 0.22-0.30x local spacing (region-dependent). Full WebRenderer-format export at `output/osn_gs_scene_latent_coverage_audit/` (5 matched stages A-E via `iteration_<N>` directories sharing world coordinates, plus per-region isolated exports) -- historical worklog 98-102 outputs left untouched.
