Follows [[project_directed_cycle_solver_contract_hardening]] (worklog 36), which precisely quantified real-snapshot closed-loop absence as 90% region-too-small / 10% candidate-recall, and worklog 36's own ambiguous-unassigned waterfall showing R2 (same_surface neighbors exist but none are in any region yet) dominant at 53-57%. This round explained WHY R2 dominates and fixed the actual mechanism.

**Root cause (proven with real 3k data)**: `_seed_core_components` builds core regions via union-find over same_surface edges, applying a "bridge veto" whenever an edge would connect two different union-find roots (`ra != rb`) — intended to guard against merging two INDEPENDENT surfaces. But since every node starts as its own singleton root, the FIRST several edges processed inside a single coherent raw same_surface connected component are indistinguishable from a genuine cross-surface merge at veto time — both look like `ra != rb`. Measured directly: an 83-node raw same_surface component (a single connected component before ANY veto) had 50 individually well-supported (`BRIDGE_WELL_SUPPORTED`) internal edges, yet fragmented into 43 separate final union-find groups (largest 11) purely from this conflation. R2 node classification confirmed this is the dominant pattern: 763/913 (84%) of R2 nodes fall in category `unseeded_component_weak_bridge_only`, with raw component sizes up to 83 — and 204/239 (85%) of R2-containing raw components got ZERO core_member anywhere in them.

**Fix (Case A, narrowly scoped)**: precompute raw same_surface connected components (over core-eligible edges, before any veto) once at the top of `_seed_core_components`. Any edge whose endpoints already share a raw component skips the bridge veto entirely and unions directly — it's seed formation WITHIN one coherent piece of evidence, not a merge of two independent ones. Edge-intrinsic vetoes (CONSENSUS_CONTRADICTED, PATH_PHASE_ALIAS, oversized-footprint-parallel-veto from worklog 35) still apply unconditionally, reordered to run before the raw-component check. `bridge_min_shared_neighbor_for_well_supported` and all other thresholds were left untouched — this was explicitly forbidden and unnecessary once the real defect (implementation, not threshold) was found.

**Result**: real 3k/5k/10k `core_member` nearly doubled (414->908, 454->882, 375->782). All negative controls (thin_slab, box_with_bridge, box_isolated_floater, box_isotropic_contamination) pass with zero false merges — verified with explicit spatial-extent checks, not just region_count.

**Other work this round**:
- Config flags renamed from worklog-numbered (`enable_worklog34_...`, `enable_worklog35_...`) to semantic names (`allow_weak_bridge_only_growth_support`, `require_nearby_parallel_evidence_for_parallel_veto`), plus the new `exempt_intra_raw_component_unions_from_bridge_veto` — all default True (canonical production behavior), ablation-only when False.
- Self-intersection check (worklog 36) gained a planarity precondition (`compute_planarity`): PCA eigenvalues, thickness/tangent-extent ratio, point-to-plane distance -> `planar_enough`/`mildly_curved_chart`/`nonplanar_ambiguous`. Nonplanar loops fail closed (`self_intersection_not_checked_nonplanar`) instead of trusting a 2D projection that isn't topology-preserving. Confirmed cylinder boundary RINGS (top/bottom circles) are legitimately `planar_enough` even though the SURFACE they bound is curved — a circle is a planar curve regardless of what it bounds.
- Frozen core-seeding replay harness (`scripts/devtools/frozen_core_seeding_replay.py`) built for fast in-process ablation (29s one-time build, ~0.2s per region-formation replay) — used for the threshold sensitivity sweep (diagnostic-only, confirmed T2/T5: small components structurally can't satisfy `bridge_min_shared_neighbor_for_well_supported=2`, but the real defect was the seed/merge conflation, not the threshold value).
- Post-ADC density sweep (cylinder/box at 1x/2x/3x) confirmed region_count is stable across density — core-seeding coverage does not structurally collapse with density changes.

**Honest disclosure — NOT fixed this round**: real 3k/5k/10k still `boundary_component_closed_count=0`/`materialized_surface_count=0` despite the ~2x core_member improvement — confirming region coverage and termination-candidate recall are genuinely separate problems (as worklog 36 suspected). A side-effect regression was found and kept (not reverted): one cylinder cap's closed loop count dropped 3->2 because the region-composition change altered downstream candidate generation context (fewer/different genuine termination candidates, 16->12) — not an ordering-solver defect (that was already hardened in worklog 36). Judged an acceptable narrow trade-off given the region-coherence improvement is large and no false merges were introduced anywhere.

**Why:** User explicitly required separating "region hasn't reached the physical perimeter" from "reached the perimeter but candidate recall is low" before touching anything, forbade threshold changes outside diagnostic sweeps, required raw/veto/seed graph topology decomposition and full R2 classification as evidence, and required an independent ablation.

**How to apply:** Do not claim real-snapshot materialization is fixed — it isn't, and wasn't required.
