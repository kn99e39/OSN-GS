**What changed.** User asked to discard the entire old synthetic Gaussian dataset (`nurbs_constructor_benchmark/gaussian_reliability_scenes.py` + `surface_region_adversarial_scenes.py`) — flat infinite-plane patches and a sine-wave "curved sheet" — because it wasn't testing genuine 3D volumetric structure. Replaced with real solids: **box** (6 faces, 12 edges, 8 corners — much richer crease structure than the old 2-plane fixture), **cylinder** (curved side wall + 2 flat end caps meeting at a circular crease), **sphere** (fully closed manifold, no boundary anywhere, uniform curvature via Fibonacci-sphere sampling). User's explicit follow-up: covariance must stay central (it already is — every primitive returns real per-point tangent-aligned covariance via the existing `covariance_from_scale_rotation` helper, not just positions).

**Scene name mapping** (old → new, same `GaussianReliabilityScene` dataclass contract preserved so downstream code barely changes): `plane`→`box_face`, `two_perpendicular_surfaces`→`box`, `close_parallel_sheets`→`thin_slab` (now genuinely opposite-facing normals ±z, not same-direction like before), `smooth_curved_sheet`→`make_curvature_sweep_scene(radius)` (now a real spherical patch, not a sine height-field; smaller radius = more curvature, larger = flatter), `isolated_floater`→`box_isolated_floater`, `isotropic_blob`→`box_isotropic_contamination`, `oversized_bridge`→`box_with_bridge`. `make_shape_ratio_sweep_scene` (pure per-Gaussian covariance-shape sweep, no surface/topology claim) kept unchanged. New `make_cylinder_phase_alias_scene()` in the adversarial file replaces the old ad hoc sine-based "long shortcut" fixture — a cylinder's circumferential periodicity means opposite-side points have exactly anti-parallel normals, which the pipeline's `abs(dot(...))` orientation-insensitive comparison reads as perfectly aligned. A very literal, real-world phase-alias stress case.

**Bugs found while building this (fixture-level, not pipeline-algorithm bugs):**
1. Sampling the WHOLE closed sphere with a fixed point count while sweeping radius collapses density at large radius (surface area grows with r²) → region count silently drops to 0. Fixed by sampling a local patch with radius-independent arc-length extent (`_spherical_patch`) instead, used specifically for the curvature sweep (the full closed `sphere` scene is separate and uses a fixed radius).
2. At `_spherical_patch`'s original `count_per_axis=9`, one specific rigid-transform variant (out of 6: 3 rotations + 2 scales + order reversal) flipped `construction_state` from `constructed` to `review_required` in the full Gaussian→NURBS pipeline. Raised default to `count_per_axis=11` (denser sampling) — all 6 variants now stable. This is exactly the kind of invariance fragility worklog 122/123 fixed for the old sine-sheet fixture; a genuinely different curved geometry can reintroduce it at low density.

**Disclosed, NOT-fixed finding**: the `sphere` scene (full closed manifold) stays 1 connected region under plain pairwise `same_surface` connectivity, but `form_surface_regions` (worklog 116's consensus-aware region formation) conservatively fragments it into ~4 regions. Verified this is NOT a false crease or false boundary (0 crease edges, 0 conflict edges on the sphere) — just conservative under-merging on a test topology (fully closed, uniformly curved, zero flat anchor) that was never in the matrix before this dataset replacement. Left as an honest, disclosed limitation for a future round; fixing region-formation itself was out of scope for a dataset-replacement task.

**Migration scope**: all 15 test files consuming these two scene modules were rewritten in the same round (user's explicit choice over "new dataset only, migrate tests later"). Full repo pytest stayed green throughout (570 passed, 1 skipped, 0 failed at completion) — see worklog 125.
