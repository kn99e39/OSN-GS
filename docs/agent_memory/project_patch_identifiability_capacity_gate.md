Two interpretation corrections carried forward from Worklog 101 review: (1) Worklog 101's "chart-level domain validity 100% (115/115)" is an identity over the already-materialized-chart denominator, not evidence that intrinsic parameterization is universally solved -- the meaningful metric is source-evidence coverage, 1089/1241 nodes (87.8%) combined, 152 (12.2%) explicitly unchartable. (2) Worklog 101's "36 control points -> minimum 36 observations" cutoff is NOT a mathematical requirement of the existing regularized NURBS solver (Tikhonov-anchored, second-difference-penalized systems are solvable even when the raw data design matrix is underdetermined) -- replaced with an explicit pre-fit identifiability contract this round.

New `torch_patch_identifiability.py`: builds the EXACT tensor-product B-spline design matrix the real solver uses (`TorchNURBSSurface._basis_tables`, never re-implemented) at a chart's fixed intrinsic (u,v) samples, computes its SVD, and judges identifiability by whether the design matrix reaches its own achievable rank `min(sample_count, control_variable_count)` -- classical full column rank when well-sampled, full row rank (every observation independently informative) when underdetermined. Sample counts below 36 are never auto-rejected; only genuine degeneracy (collapsed u/v extent, real rank deficiency) fails. New `torch_adaptive_patch_capacity.py`: candidate B (`select_adaptive_quadratic_capacity`, degree fixed 2, largest identifiable grid 3x3-6x6, aspect-ratio tiebreak) and candidate C (`select_support_adaptive_capacity`, degree 2 tried first then degree 1 fallback, 2x2-6x6, prefers highest order then highest capacity) -- both driven entirely by pre-fit identifiability, never fit/held-out error (AST-verified). New `torch_chart_overlap_consistency.py` evaluates (never merges/re-fits) position and normal disagreement between independently-fitted overlapping charts' patches over their shared evidence.

Real 7-region paired replay (baseline_compatible 2900/final, same Worklog 101 chart atlas, no fallback): candidate C raised identifiable-chart share from A's 23.5% (27/115) to **68.7% (79/115)** -- but VALID_SUPPORTED stayed exactly **2/115 (1.7%) for A, B, and C alike**. None of the 52 newly-identifiable charts under C reached a safe fit; 97.5% of C's identifiable charts (48 unsafe + 29 extrapolative) remained unsafe. Overlap consistency (evaluation only, no reconciliation attempted) showed MORE overlapping pairs reached fitting under C but with WORSE, not better, position/normal disagreement than A/B.

Decision C: TENSOR_PRODUCT_PATCH_STILL_FAILS. Most valid charts become algebraically identifiable under B/C, but fitted patches remain predominantly unsafe/extrapolative regardless -- this is a genuine limitation of the current local tensor-product NURBS fitting/representation itself, not intrinsic parameterization (see [[project_intrinsic_integrability_local_chart_atlas]]) or excessive fixed capacity. Do not return upstream to chart construction or parameterization.
