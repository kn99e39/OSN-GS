Worklog 99 resolves Worklog 98's open question: whether the remaining extrapolative/unsafe outcome is caused by fixed NURBS capacity, generic LSQ fitting, curve-network-vs-point-cloud construction, or the tree-integrated UV domain itself. Visible Gaussian training, ADC, region ownership, Worklog 95's estimator, continuous support contract, Worklog 98's synchronized tangent-frame field/coherent components, each component's input 3D evidence, held-out evaluation, and the existing extrapolative/unsafe/valid_supported definitions are all fixed. No candidate tuned using held-out results.

New module `osn_gs/surface/torch_parametric_domain_validity.py`: characterizes each Worklog 98 coherent component's already-computed (u, v) BEFORE any candidate is fit. Fits a local least-squares affine Jacobian (`delta_position ~= J @ delta_uv`) over each point's UV-space kNN neighborhood; compares the cross product of J's two columns against the point's actual normal to detect orientation reversal/foldover; uses J's singular values for local Jacobian singularity and condition number (= extreme stretching relative to local median 3D spacing). Also reuses Worklog 98's own holonomy edges to report POSITION-based (not just orientation-based) cycle drift. A single detected fold invalidates the whole component's domain, fail-closed, never PCA-repaired.

New module `osn_gs/surface/torch_adaptive_nurbs_capacity.py` (candidate B): deterministic capacity selection using ONLY Worklog 98's own U/V curve-family counts, component sample count, and (u,v) aspect ratio -- never fit/held-out error (AST-verified). Feeds directly into Worklog 97's unchanged `fit_torch_visible_surface_from_uv` (already has second-difference/Tikhonov regularization built in).

New module `osn_gs/surface/torch_gordon_curve_network_surface.py` (candidate C): classical Gordon transfinite interpolation (`S = S1 + S2 - S12`) approximated for noisy scattered OSN-GS evidence by bucketing (u,v) into discrete U/V levels (count fixed by Worklog 98's own curve-family sizes, never fit-error-driven), fitting a real least-squares quadratic curve per level, and evaluating the classical loft+correction formula on a regular grid used directly as the B-spline control net. Classical principle and OSN-GS approximation explicitly separated in the docstring. Fails closed (`insufficient_populated_curve_levels`) if too few levels have enough points -- no fabricated boundary curves, no closed-boundary requirement.

Real 7-region paired replay (baseline_compatible checkpoints 2900, final; same components as Worklog 98): **combined 80.4% (37/46) of orientation-coherent components already fail parameter-domain validity BEFORE any of A/B/C is even attempted** -- 75.9% (22/29) at 2900, 88.2% (15/17) at final. 100% of the invalid cases at both checkpoints are `uv_orientation_reversal_or_foldover` (zero duplicate-UV or singular-Jacobian cases). Among the small domain-valid remainder (all 8-40 points, tiny), valid_supported was effectively 0% for all three candidates: only A/B reached 0.59% at 2900 (a single 11-point component), everything else was 0% at both checkpoints. Candidate B's adaptive capacity converged to the minimum 4x4 for every domain-valid component (sample counts too small to justify more). Candidate C frequently failed with `insufficient_populated_curve_levels` on the same small components.

Decision D: PARAMETER_DOMAIN_LIMIT. Since 80.4% of coherent components never reach a fair A/B/C comparison, and none of the three candidates achieve meaningful valid_supported even where the domain is valid, this cannot be attributed to NURBS capacity (B) or curve-network-native construction (C). Worklog 98 solved tangent-frame ORIENTATION coherence but not a globally usable parameter-DOMAIN construction. The next architecture decision must concern intrinsic parameterization itself (an alternative to the current tree-integrated arc-length approach), not NURBS capacity or fitting formulation. Do not return to curve seeding. See [[project_synchronized_tangent_frame_curve_lattice]] for the Worklog 98 baseline this gate evaluates.
