Worklog 100 found forcing one global (u,v) chart over a whole Worklog 98 coherent component is the wrong scale for most components (global differential integration only raised domain-valid 15->18/46; a fixed local-injectivity refinement rescued zero additional components). Worklog 101 drops the one-chart-per-component assumption. Note on interpretation: the user explicitly corrected that low differential residual plus failure of the fixed 3-iteration reweighted solver does NOT mathematically prove the underlying surface is intrinsically non-parameterizable -- candidate C was a fixed fold-aware reweighted solve, not a general non-existence proof. The evidence was sufficient only to stop forcing one chart per whole component.

New `torch_intrinsic_chart_atlas.py`: a chart is a subset of the SAME continuously-supported source graph (never Euclidean bbox/PCA rectangle/convex hull/physical boundary). Deterministic construction: first anchor = centroid-nearest node; BFS hop-count RINGS (graph-topological, not tuned Euclidean/PCA radius) from that anchor; at each ring, re-solve Worklog 100's `integrate_global_differential_uv` over ALL internal supported edges (not a spanning tree) and validate with the corrected validator; keep growing while valid, stop at the first invalid ring, keep the last valid ring as the maximal chart. Subsequent anchors = farthest-uncovered node by BFS graph distance from current coverage (deterministic, min-index tiebreak) -- this anchor selection is coverage-only, never recorded as physical boundary/crease/feature. Chart growth never excludes already-covered nodes, so charts naturally overlap; edges spanning two charts (or chart-to-uncovered) are tagged `seam_edges` (parametric label only). Each chart inherits the parent's synchronized `e_u`/`e_v`/normals unchanged (no independent PCA re-estimation) -- only the chart's own candidate-B UV gauge is chart-local. New `torch_chart_curve_lattice.py` restricts Worklog 98's `build_curve_lattice` unmodified to the chart-scoped component, then post-hoc truncates any curve the tracer walked past the chart's own node membership (found and fixed a real bug: truncating a bidirectional curve with one left-to-right scan wrongly discarded a valid forward half whenever the backward half left the chart first -- fixed to truncate each direction independently outward from the anchor's own array row).

Real 7-region paired replay (baseline_compatible 2900/final): chart-level domain validity is **100% (115/115)** combined, vs the single-global-chart baseline's 39.1% (18/46, identical to Worklog 100 candidate B). **CORRECTION (Worklog 102): this 100% is an identity over the already-materialized-chart denominator, not evidence that intrinsic parameterization is universally solved -- the meaningful metric is source-evidence coverage: 1089/1241 nodes (87.8%) combined, with 152 (12.2%) explicitly unchartable.** But 92.2% (106/115) of domain-valid charts are smaller (median 9 nodes) than the fixed 6x6 NURBS grid's own control-point count (36) -- reported as `CHART_DOMAIN_VALID_BUT_INSUFFICIENT_PATCH_SUPPORT`, kept separate from `PARAMETER_DOMAIN_INVALID`. The 9 charts (7.8%) large enough to actually reach the fixed fitter all failed: 8 unsafe, 1 extrapolative, 0 valid_supported.

Decision B: VALID_CHARTS_EXIST_BUT_CURRENT_PATCH_MODEL_FAILS. The intrinsic-parameterization problem is operationally resolved at chart scale. The next architecture gate must address the local/adaptive parametric patch representation/fitting model itself -- do not enlarge charts artificially to satisfy the fixed 6x6 grid. See [[project_intrinsic_parameterization_architecture_gate]] for the Worklog 100 baseline this gate improves on.
