Worklog 61 (docs/worklogs/61_real_visible_chart_boundary_materialization.md) built `osn_gs/surface/torch_region_parametric_chart_boundary.py` — a NEW visible-NURBS materialization path that constructs a chart boundary from a region's own already-accepted topology (`SurfaceRegionCandidate.internal_accepted_edge_ids`, unmodified), independent of whether any physical surface-termination evidence exists at all. Completely separate from, and additive to, [[project_visible_boundary_eligibility_contract]] (worklog 54)'s `eligible_closed_boundary` physical path — that path's own code is 100% untouched this round.

**Mechanism**: project region members into one canonical tangent-plane 2D frame (`construct_canonical_region_tangent_frames`, unmodified), then trace the OUTER FACE of the region's accepted-edge adjacency graph via a leftmost-turn walk — generalizes `torch_patch_boundary._trace_oriented_mask_loops`'s grid-graph turn-angle technique (`atan2(cross,dot)`) to an arbitrary graph. Verified directly on a synthetic concave hexagon with an interior chord: the trace correctly follows the real (concave) boundary and never cuts across the chord — proof it is NOT a convex hull. Only a validated single simple closed, non-branching, non-self-intersecting loop (`validate_simple_closed_loop`, unmodified, reused) is eligible; every other outcome is a stable typed rejection (`parametric_chart_insufficient_topology`/`_topology_open_or_branching`/`_self_intersection_failed`/`_no_canonical_tangent_frame`).

**Segment classification** (never disguised as physical): each boundary edge's endpoints are checked against existing `WorldSpaceBoundaryHalfEdgeCandidate.boundary_reason` (unmodified) — `observed_support_termination`→`physical_termination`, `crease_discontinuity`→`crease`, other typed evidence→`observation_frontier`, no typed evidence at all→`partition_seam` (pure topology artifact, disclosed honestly).

**Wiring**: `VisibleSurfaceConstructionResult` gained `region_parametric_chart_boundaries`/`parametric_chart_materialization_attempts`/`materialized_parametric_chart_surfaces` (all defaulted `()`, backward compatible) and a new `eligible_parametric_chart_surfaces()` entry point — deliberately NOT merged into `eligible_materialized_surfaces()` since [[project_eligible_boundary_continuation_bridge]] (worklog 56) and other existing consumers assume every entry there is physically terminated.

**Results**: negative control (cap 64) physical counts byte-identical to worklog 47-60 baseline (Box 6/6, Cylinder 2/2, Sphere 0/0, Thin-slab 3/3) — zero regression. Parametric path additionally materializes Box 4, Cylinder 1, **Sphere 1** (physical stays 0; the sphere gets a real materialized chart surface only under the separate `eligible_parametric_chart_boundary` provenance, never claimed as physical), Thin-slab 3 (1 `partition_seam` segment disclosed). Real 5k/10k (cap 2048): combined (physical+parametric) materialized surfaces 3→92 and 4→78 — but note the physical baseline itself shifted (2→3 for 5k, 0→4 for 10k) because `output/osn_gs_scene/*/checkpoint.pt` was overwritten by a completed training run between session rounds, unrelated to this change (see [[project_osn_gs_direction]] update below). Real 3k at cap=2048 crashes on a **pre-existing, unrelated** `KeyError` in `torch_gaussian_surface_region_formation.py` (worklog 111-123, 2026-07-30 code, confirmed via git blame and reproduced with the unmodified worklog-56 script) — newly exposed by the changed checkpoint content, not by this round's code; reported at cap=1024 instead (1→47) as a substitute. Full pytest 760→772.

**How to apply:** any future consumer wanting parametric-chart geometry must call `eligible_parametric_chart_surfaces()` explicitly and keep its provenance visibly separate from `eligible_materialized_surfaces()` — never combine them silently. If real-checkpoint region formation crashes again at cap=2048, it is very likely this same pre-existing `bridge_by_pair`/`consensus_by_pair` key-mismatch defect (untouched, unscoped for worklog 61) — check that before assuming a new regression.
