Follows [[project_region_quality_boundary_admission_repair]] (worklog 34), which diagnosed but explicitly did NOT fix C9/C11. This round fixed both, independently, in one batch.

**C11 fix (directed boundary ordering, `osn_gs/surface/torch_directed_boundary_ordering.py`)**: box_face (27-member post-ADC region, 19 genuine candidates, same-region partner median 18) fragmented into 6 open chains under the old mutual-agreement + greedy-augmentation heuristic — NOT candidate scarcity. Root cause traced precisely: 13/19 nodes had >1 directionally-compatible successor; greedy per-node score maximization is only locally optimal, so mutual agreement held for only 11/19 edges and the rest fragmented under score-ordered greedy augmentation with no mechanism enforcing a single ring. Fixed by replacing the heuristic with an **exact maximum-weight one-in/one-out matching (Hungarian algorithm, O(n^3), bounded per-region with a 150-candidate defensive ceiling)** over the SAME compatibility edges — structurally guarantees in-degree<=1/out-degree<=1, decomposes into disjoint simple cycles/open paths, never force-closes. Result: box_face 6 fragments -> 1 closed 15-node loop + 1 open 3-node remnant, `materialized_surface_count` 0->1. Verified: rigid-rotation/translation/uniform-scale EXACT invariance on frozen synthetic rings; open-chain/sparse-gap/Y-junction/duplicate-edge/two-disjoint-loops negative controls all correctly reject false closure; NURBS boundary_residual=0.054 (low) and total-turning-angle exactly ±2π (simple non-self-intersecting loop) on the recovered box_face loop.

**C9 fix (region formation, `osn_gs/surface/torch_gaussian_surface_region_formation.py`)**: `_seed_core_components`'s bridge-veto itself was mostly legitimate (83% of real-3k cross-component pairs genuinely have only 1 fragile bridge edge — correctly vetoed, untouched). But traced precisely: 30% (56/184) of pairs with >=2 cross edges had at least one individual edge PASS `_evaluate_bridge_veto` (`well_supported_connection`) yet still never merged. Cause: a separate parallel-shortcut override re-thresholds `normal_direction_separation_over_thickness` (normalized by individual-Gaussian `normal_thickness` — same category of quantity worklog 30-33 already found unusable on real long-horizon data) at a fixed "4.0", vetoing edges the bridge check already accepted. Measured: this metric heavily OVERLAPS between same_surface (median 108) and parallel_separate (median 645) edges on real data — does not discriminate at any fixed threshold. The override's own comment said it required "nearby parallel-separated evidence" but the code never checked for that — only the direct pair's own mis-scaled metric. Fix: added `consensus.contradicting_parallel_neighbor_count > 0` (already-computed field) to the condition, making the override actually implement its documented intent. Result: real 3k/5k/10k `consensus_attached` 1->12 / 0->9 / 0->5, max core-component size grew (16->17 / 17->18 / 21->22, worklog-34 baseline). Threshold values themselves untouched; core-to-core merge policy untouched.

**Ablation proof of independence**: 4-way matrix (A baseline / B C11-only / C C9-only / D combined) on real 3k/5k/10k + box_face — B changes ONLY box_face (identical to A on real snapshots), C changes ONLY real-snapshot region metrics (identical to A on box_face), D reproduces exactly C's region numbers + B's box_face closure with no interaction cost.

**Still NOT solved (honest disclosure)**: real 3k/5k/10k `boundary_component_closed_count` stays 0 and `materialized_surface_count` stays 0 — C9's fundamental limiter (median 1-2 genuine termination candidates per region, need >=3 for a closed loop) was NOT resolved; the dominant weak-bridge veto reason (91%, `too_few_shared_same_surface_neighbors_for_confident_bridge`, i.e. `bridge_min_shared_neighbor_for_well_supported=2`) is explicitly the kind of threshold this round was forbidden from loosening. box_face(cap=27, forced downsample) itself only reached 15/19 nodes in one closed loop, not the full 19.

**Why:** User explicitly separated C9 and C11 as independent problems, required isolated reproduction+fix for each, forbade threshold/cap/admission-policy loosening, forbade forcing loops closed, required an ablation proving independent contribution, and required full pytest only once at the end with timing reported.

**How to apply:** Do not claim real-snapshot boundary linking is "fixed" — it structurally cannot close loops until either the bridge-veto shared-neighbor threshold is revisited (needs separate authorization, touches region-merge policy) or genuine termination-candidate generation improves. Next round's clear target per worklog 35 §19: (1) investigate whether `bridge_min_shared_neighbor_for_well_supported=2` is structurally too strict for real data density (needs authorization), (2) the residual 3-node open fragment on box_face(cap=27) — the matching-based ordering fix is otherwise solid and can be trusted as production.
