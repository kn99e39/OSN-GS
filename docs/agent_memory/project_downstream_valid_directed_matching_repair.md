Worklog 53 (docs/worklogs/53_downstream_valid_directed_matching_repair.md) confirmed and fixed the real defect [[project_directed_matching_objective_audit]] (worklog 52) missed: for region 56 (3k, cap 2048), pure max-score Hungarian matching selects a mutual pair (`1039800↔819956`, combined score 5.89) that `_decompose_into_paths_and_cycles` has always required length≥3 to accept as a closed loop — a 2-cycle is structurally always discarded downstream, so scoring it as valid wastes both nodes' entire in/out capacity for nothing.

**Fix 1** (`osn_gs/surface/torch_directed_boundary_ordering.py`): `_solve_one_in_one_out_assignment` now accepts a `forbidden` edge set; `_find_two_cycle` detects mutual pairs deterministically; `_matching_forbidding_two_cycles` recursively tries forbidding each direction of a detected 2-cycle and picks whichever branch scores higher (bounded at 16 branch expansions, same "explicit fail-closed ceiling" philosophy as `_EXACT_MATCHING_MAX_CANDIDATES_PER_REGION`). No new edges, no closure bonus — exhaustive brute-force confirmed the true 2-cycle-free optimum for region 56 is a 4-node OPEN path (score 7.224), not the feasible 3-cycle (6.4619, actually lower) — forcing the cycle would itself have been an unauthorized closure bonus, correctly not done.

**Fix 2 (found while verifying Fix 1)**: applying Fix 1 alone regressed the thin_slab negative-control fixture (closed 3→2, materialized 3→0) at cap 64. Root cause: `recover_directed_boundary_components` picks between direct-tangent and reverse-tangent orderings scene-wide via `quality()`, which counted `ordering_state == "ordered_closed_loop"` components without checking self-intersection. Fix 1 legitimately resolved a 2-cycle in a DIFFERENT region of the reverse-tangent candidate set, raising reverse's closed-loop count enough to win the orientation comparison — which incidentally dragged in an unrelated, PRE-EXISTING self-intersecting 16-node loop in reverse's region 0 (present even with zero 2-cycles involved, confirmed via monkeypatch reproducing the pre-Fix-1 code). Fixed by making `quality()` only count a component as closed if it ALSO passes `validate_simple_closed_loop` (the same check materialization already applies downstream) — a latent defect Fix 1 exposed, not one it created.

**Result:** region 56 now gives one coherent 4-node open path instead of two fragments (one being a wasted 2-cycle); region 52 (3k) and 10k region 52 completely unchanged (no 2-cycle in either, correctly left open per worklog 52's findings). Real 3k/5k/10k physical-candidate and closed-region counts unchanged (154/148, 185/182 closed[130,141], 125/122) — this was a correctness fix, not a loop-closer. Negative-control fixtures (Box 6/Cylinder 2/Sphere 0/Thin-slab 3 at cap 64) fully restored to baseline after Fix 2; box density-sweep (mult 1/2/4/8 × cap 128/256) region_count=6 preserved throughout. Full pytest 720 passed / 1 skipped unchanged.

**How to apply:** if a future round touches `_max_weight_one_in_one_out_matching` or `recover_directed_boundary_components`'s orientation comparison, re-verify BOTH: (1) the 2-cycle branch-and-bound still respects `_MAX_TWO_CYCLE_BRANCH_EXPANSIONS`, and (2) `quality()`'s self-intersection-aware closed-loop counting — these two are now coupled (a matching-level fix can flip which orientation wins scene-wide, surfacing latent issues in the OTHER orientation). Always re-run the full negative-control fixture table (Box/Cylinder/Sphere/Thin-slab), not just pytest, after any ordering change — pytest did not catch this regression on its own.
