Worklog 95 is the first implementation batch following Worklog 94's Decision 3 (stop constructor-level redesign via representation swaps). It is a genuinely new constructor path, not a diagnostic: region-owned visible Gaussians -> latent surface support -> structural curve network -> NURBS patch -> held-out validation, with NO dependency on Worklog 82/83/89's raw Gaussian-center same-surface kNN graph, chart-unit assembly, or full-region face-incidence topology. Visible Gaussian training, ADC, region ownership, and the existing NURBS fitter (`fit_torch_visible_surface_lsq`) are all fixed and unmodified.

New modules:
- `osn_gs/surface/torch_latent_surface_support.py`: MLS-style position-only local surface estimator. Never reads covariance. `build_latent_surface_support(points)` builds from a region's owned centers; `.query_batch(positions)` projects arbitrary 3D positions via weighted-PCA local plane fit (k=16 neighbors, Gaussian kernel, 2 MLS iterations) and reports tangent frame + explicit `supported` bool (gated on support-radius, effective-neighbor-count, and local planarity -- never fabricates a plane for unsupported queries).
- `osn_gs/surface/torch_latent_surface_curve_network.py`: seed curve reuses the EXISTING unmodified Worklog 79/80 sparse parametric chart boundary (`construct_region_parametric_chart_boundaries` output, already produced by the fixed canonical-construction pipeline) as curve seeds -- not a new boundary reconstruction. Each seed edge is densified (6 steps) with per-step MLS projection; loses support -> truncates immediately (no gap bridging). Surviving seed points spawn surface-following transversal curves (12 steps, walking the local tangent direction most orthogonal to the seed direction, signed toward the seed centroid) that also truncate on loss of support. Interior "rung" curves connect transversal curves at equal step depth (only already-validated points, no new fabrication). No convex hull / bounding box / PCA-rectangle / alpha-shape fallback anywhere.
- Validation script `scripts/devtools/latent_surface_curve_network_prototype_replay.py` reuses Worklog 87's own PCA-UV checkerboard `_holdout` split unmodified: the latent surface estimator and the ENTIRE curve network are built only from the train half; the held half never influences curve construction and is used only to validate the fitted NURBS patch (EXTRAPOLATION_BOUND=4.0, BASE_GRID=6/degree=2, identical to `evaluate_fit`'s existing convention, for direct comparability with the Worklog 89/94 baseline).

Real 7-region replay (baseline_compatible checkpoints 2900 and final): regions with usable seed curves 5/7, regions producing a curve network 4/7 (region 3's seed walk fails immediately; regions 4/5 have no eligible chart at all -- same as every prior worklog), materialized patches 4/4 at both checkpoints. **valid_supported: 0.000%/0.051% (Worklog 89/94 RAW_CENTER_BASELINE) -> 2.64%/11.95% (nonzero at both checkpoints). unresolved: 87.98%/84.73% -> 42.60%/32.51% (cut roughly in half or better).** Most of the unresolved reduction is absorbed by extrapolative (40.05%/31.12%) and unsafe_geometry (14.72%/24.43%), not valid_supported. Held-out p95 (7.96/7.76) is worse than baseline's 2.67-3.90. Train-only-built latent surface reports 55.98-59.53% of full region evidence unsupported -- the current support-radius (3x local spacing) is somewhat tight for the checkerboard-sparsified train set, an honest measured limitation.

Answers the architecture question partially: removing raw Gaussian-center connectivity and constructing curves on a latent surface support DOES materially increase valid_supported (0 -> nonzero at every checkpoint) and substantially reduces unresolved evidence, but the large majority of evidence is still extrapolative or unsafe, and 3/7 regions produce no curve network at all. This is a real but incomplete first prototype, not a finished replacement for Worklog 89's constructor. See [[project_surface_evidence_representation_gate]] for the Worklog 94 baseline this compares against.
