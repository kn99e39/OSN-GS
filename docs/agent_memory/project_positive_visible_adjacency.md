Worklog 103 (2026-08-21, `arch/2dgs-coverage-first-surface`): the user reframed Worklog 102's 92.69% percolation NOT as a failure of the "connectivity-by-default, cut-by-evidence" principle, but as a flaw in the graph it was applied to (spatial kNN minus contradiction cuts, which let 74.7% of spatial edges stay connected purely by absence of contradiction, never actually co-observed). Central inversion: spatial kNN becomes a pure candidate-relation generator; the graph visible topology is actually built from requires **POSITIVE observation support** (`POSITIVE_VISIBLE_CONTINUATION`), not merely "not contradicted".

New module `osn_gs/surface/torch_positive_visible_adjacency.py`. Reuses WL102's already-correct `_per_view_status_codes`/`_project_to_camera` (canonical Phase-C wrappers) and WL98/102's shape-operator/residual machinery via direct import -- no reimplementation. `torch_observation_evidence.py` and `torch_maximal_visible_connectivity.py` (WL102) are both left completely unmodified; WL102 is re-run unchanged as the review-export baseline comparison (view H).

7 mutually-exclusive per-edge relation states: `POSITIVE_VISIBLE_CONTINUATION`, `CUT_KNOWN_FREE_SPACE`, `CUT_OCCLUDED_DOMAIN`, `CUT_VISIBLE_GEOMETRIC_DISCONTINUITY`, `CUT_POSITIONAL_SHEET_SEPARATION` (both reused from WL98/102, applied only as a SECONDARY gate to edges that already cleared the observation test), `UNRESOLVED_OBSERVATION_CONFLICT` (positive AND contradiction both present for the same edge), `UNKNOWN_NO_POSITIVE_OBSERVATION` (never co-observed, or co-observed but no clean signal). Multi-view aggregation has NO percentage/majority threshold anywhere (directive explicitly forbade one): any_positive (>=1 clean view) AND no contradiction => positive; both present => unresolved conflict.

10 synthetic fixtures (A-J) required, all pass (14 new tests in `tests/test_positive_visible_adjacency.py`, reusing WL102's fixtures via import -- `_Orientation`/`_lookat_world_view`/`_build_camera`/`_grid`/`_flat_orientation`/`_cylinder_band`/`_wall_pair_with_gap`/`_wall_gap_wall_camera_evidence`/`_procedural_evidence`/`_LOCAL_CONFIG`). New helper `_splatted_evidence`: 2-pass point-cloud splatting (pass 1 = exact self-write at each point's own rounded pixel, nearest-wins only for genuine collisions; pass 2 = dilate into still-empty pixels only, for screen-corridor continuity) -- avoids both the CPU fallback renderer's blend imprecision AND a naive single-pass dilation's tendency to let one point's disc overwrite an adjacent point's own true depth when points are sub-pixel-spaced (a real failure mode hit and fixed while tuning fixture B: at 0.1-world-unit grid spacing with certain camera FOVs, adjacent points project <1px apart, so pass-1-then-pass-2 ordering is required, not merely picking a big enough radius). Key new fixtures beyond WL102's 8: H (no camera at all => zero positive edges, all singletons, even though the identical input is WL102's own "1 component" fixture), I (one positive view + one view that simply cannot observe the region at all => still connects, absence of observation is not a contradiction), J (one view positive + one view genuinely contradicting the same edge => `UNRESOLVED_OBSERVATION_CONFLICT`, not connected).

**Real-scene measurement: mixed, not a clean win.** Same checkpoint as WL96-102 (`output/arch_2dgs_coverage_first_surface/2dgs_run1/30000`, 1,190,469 surfels), all 161 train cameras. Of 5,132,180 spatial candidate edges, exactly 1,295,809 (25.3%) received co-observation -- identical to WL102's own `observation_evaluated_edge_count`, a strong cross-check that both modules reuse the same range-based screen-walk correctly. Of those, 1,043,908 (20.3% of all spatial edges) became `POSITIVE_VISIBLE_CONTINUATION` after the secondary geometric gate (77,496 discontinuity + 153,302 positional demotions), 1,616 known-free-space, 1,380 occluded, 18,107 unresolved conflict; the remaining 3,836,371 (74.7%) stayed `UNKNOWN_NO_POSITIVE_OBSERVATION`.

Result: **largest component fraction dropped from WL102's 92.69% to 10.50%** (124,984 surfels) -- table and patio are now genuinely separate components (confirmed visually: table top renders as a single solid color distinct from the surrounding patio floor, unlike WL102's near-uniform single-color scene). But **component count exploded from 13,585 to 768,829**, with **63.4% of all surfels (754,988) becoming isolated singletons** (mean component size 1.548, median 1). Visual review of the 8 required PNG previews (`output/osn_gs_positive_visible_adjacency/preview_png/`) shows large, well-observed, repeatedly-seen flat surfaces (table top, patio floor) resolve into clean single components, while low-evidence-density complex regions (hedge/background foliage) fragment into rainbow speckle (thousands of tiny components) rather than either percolating (WL102) or staying coherently connected. Occluded/free-space termination points remain sparse (matching the small counts) and cluster near the hedge boundary -- confirms most disconnection in the final result comes from absence of positive observation (`UNKNOWN`), not from positive occlusion evidence.

Full regression 1198 passed, 1 skipped (+14 from WL102's 1184). **Neither WL102 nor WL103 is adopted as architecture.** They sit at opposite ends of the same axis (no-contradiction-connects vs. positive-support-required) and both fail on the real scene in opposite directions (over-connection vs. over-fragmentation). If there is a next step it likely needs either higher co-observation density (more cameras, more tolerant corridor test) or a principled middle ground between the two extremes -- but this batch does not make that call.
