Follows [[project_per_representative_reliability_gate_trace]] (worklog 31), which found two independent bottlenecks: (A) contextual reliability collapse (tangent_residual gate dominant failure) and (B) manifold-affinity-graph candidate scarcity (95-97% of kNN pairs never become candidates, causing region_seed_core=0). This round diagnosed and attempted to fix the shared root cause: a single representative Gaussian's own `tangent_major_scale` (covariance footprint size) was being reused as BOTH the contextual-evidence local radius/residual denominator AND the manifold-affinity candidate radius/residual denominator — two semantically different "local scale" concepts conflated into one.

**LocalEvidenceScale (shipped)**: per-representative `cbrt(characteristic_scene_length³ / (resolution³ · source_count))`, where `characteristic_scene_length = 2·sqrt(trace(cov(points))/3)` is rotation/translation/uniform-scale-INVARIANT (trace is orthogonal-invariant), and `source_count` reuses the already-computed selection-time voxel-cell/mode member count (no new computation). Wired into `compute_full_neighborhood_evidence(..., local_evidence_scale=...)` (new optional param, defaults to old `tangent_major_scale` behavior when omitted — fully backward compatible) via `TorchOSNGSPipeline._construct_canonical_with_full_evidence`. First attempt used an axis-aligned bounding-box span for `cell_volume`, which broke `test_construction_outcome_is_stable_under_rigid_rotation_translation_and_uniform_scale` (4≠1) — axis-aligned boxes aren't rotation-invariant. Fixed by switching to the trace-based characteristic length. Result on real 3k/5k/10k snapshots: `contextual_insufficient` count dropped sharply (23→5, 30→0, 32→1), `final_reliable` improved at 5k/10k (7→11, 9→12) but NOT at 3k (7→3) — net effect is NOT uniformly positive, disclosed honestly rather than oversold.

**RepresentativeGraphScale (rejected, reverted 3x)**: needed for `build_manifold_affinity_graph`'s candidate radius (`scale_radius_multiplier * tangent_major_scale`) and pairwise `mutual_tangent_residual` denominator — worklog 31's real bottleneck. Three candidates tried, ALL broke `test_full_cloud_continuation_shell.py::InvarianceTest::test_region_and_reliable_counts_stable_under_rigid_transform` and/or the density-preserving-selection invariance test:
1. Representative-to-representative kNN median distance (per-representative, reuses the already-built cdist/knn_indices in `build_manifold_affinity_graph`, zero extra cost) — broke invariance.
2. Reusing `evidence.mean_spacing` (= `reliability.contextual.neighbor_spacing`, already threaded into `_compute_pair_metrics` but unused for residual) — broke invariance WORSE (new failures appeared, e.g. density-sweep test).
3. Reusing `local_evidence_scale` directly (per-representative, already proven invariant) — still broke invariance (same specific test, numbers changed but still failed).
4. A single scene-wide scalar (`cbrt(cell_volume / median(source_count))`, broadcast to all representatives, sacrificing per-representative locality for robustness) — median source_count itself measured nearly identical under rotation (6.0 vs 6.0), but the SAME specific invariance test STILL failed (1≠5).

**Root cause of why every graph-scale candidate failed**: representative SELECTION itself (the axis-aligned voxel grid in `torch_density_preserving_representative_selection.py`) is already documented as not exactly rotation-invariant (a different representative subset can be picked under rotation) — an ALREADY-ACCEPTED limitation. The OLD `tangent_major_scale` tolerated this because it's an intrinsic per-Gaussian property (nearby Gaussians in the same area have similar covariance size regardless of which one gets picked as representative). Every new candidate is instead an AGGREGATE quantity over the representative subset's own positions/counts, which inherits and amplifies that non-invariance. Fixing this properly would require touching representative selection's own rotation-robustness — explicitly out of scope this round (FPS/selection policy changes forbidden).

**Why:** User explicitly required success criteria to include invariance preservation (§17 of the task) as a hard requirement equal to fixing the bottleneck — "Materialized NURBS 개수만 늘리고 false surface connection이나 inaccurate boundary를 허용하면 실패다." Given repeated invariance failures, the responsible choice was reverting bottleneck-B's fix rather than shipping a regression.

**How to apply:** `region_seed_core=0`/`region_count=0` on real long-horizon snapshots is STILL unresolved after this round — do not assume worklog 32 "fixed" region formation. Any future attempt at RepresentativeGraphScale must either (a) first make representative selection itself rotation-robust (a separate, larger task), or (b) find a scale that's provably invariant AND doesn't depend on the exact representative subset's arrangement — the 4 candidates tried here all failed the second requirement. `-surf` (osn-gs benchmark) does NOT exercise any of this work — it routes through `_initialize_canonical`/`_canonical_initial_covariance` (a completely different, untouched code path from `_construct_canonical_with_full_evidence`), confirmed by code read; don't expect `-surf` results to reflect this thread's fixes.
