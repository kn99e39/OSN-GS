Worklog 101 (2026-08-21, `arch/2dgs-coverage-first-surface`): tested the user's hypothesis that [[project_bilateral_interface_region_merge]] (WL100)'s very low merge count (1,742/1,763,096 interfaces accepted) reflects a circular support-starvation deadlock -- conservative WL97-with-gate init over-segments a smooth surface -> a small fragment's FIXED global k=8 neighborhood is dominated by the opposite region (masked out) -> fewer than 2 same-region neighbors survive -> UNSUPPORTED -> can never merge, regardless of true geometry.

New module `osn_gs/surface/torch_region_adaptive_support_merge.py`, added SEPARATELY (WL100's own module untouched, imports its `_fit_region_conditioned_shape_operators` unmodified). `SUPPORT_MODE_FIXED_MASKED_KNN` reproduces WL100 byte-for-byte (verified: identical `subset_ids` on real fixtures). Built complete multi-label rejected-interface attribution (`insufficient_region_support_A/B/both`, `interface_unique_support_failure`, `interface_extent_failure`, `directional_residual_failure_A_to_B/B_to_A`, `positional_continuity_failure`, `bilateral_smooth_fraction_failure`, `would_pass_geometry_tests_but_for_support`) and region-size-binned support stats (bins 1/2-4/5-8/9-16/17-32/33-64/>64).

**Real-scene measurement: support starvation is NOT material.** Only 0.29% (5,186/1,761,354) of rejected interfaces would have passed everything else if support alone were fixed. Region-size bins DO show the expected correlation (singleton regions 0% supported by construction, 2-4 members 40.8%, 5-8 members 87.6%, >64 members 98.3%) -- but the dominant rejection reasons are interface-level floors unrelated to per-node support: `interface_unique_support_failure` 98.5%, `bilateral_smooth_fraction_failure` 97.7%, `interface_extent_failure` 87.0%. Most rejected interfaces are simply too small/narrow regardless of support -- a granularity property of the conservative initialization, not a support-acquisition bug.

Implemented `SUPPORT_MODE_ADAPTIVE_SAME_REGION_LOCAL` anyway to cross-check the null result empirically: instead of masking a fixed global k=8, search a bounded pool (k=32, derived from `neighbor_count*4`, not swept) for same-region neighbors within `local.spatial_connect_spacing_multiplier * local_spacing` (the SAME locality contract the candidate graph itself uses, no new radius). Bilateral semantics unchanged (still AND, not min; unsupported never counts as smooth). 12 new synthetic tests pass, including a deterministic "finger embedded in denser opposite-region material" fixture proving FIXED support<2 while ADAPTIVE support>=2. Found and disclosed a real limitation: reusing a boundary node's own raw `local_spacing` as the locality bound fails when that node sits near much denser opposite-region material (the bound itself gets contaminated too small) -- correctly resolved to UNSUPPORTED per the directive's own "do not fabricate support" instruction, not worked around.

**Real-scene A/B: adaptive support causes a genuine percolation regression.** Largest subset fraction jumped from 22.91% (WL100/FIXED) to **42.13%** (ADAPTIVE) even though merges only roughly doubled (1,652->3,513) -- a cascading/transitive effect the single-round "would_pass_if_supported" proxy (0.29%) did not capture. Traced the exact WL100 patio-seed (node 117922, initial region 5052) and hedge-seed (node 711179, initial region 555): they remain in DIFFERENT final subsets under adaptive support (the specific WL99 lineage stays blocked) -- but visual review of the export showed a NEW giant merge inside the hedge/background area itself (left half of the hedge went from multicolor fragments to one uniform color), the same kind of dense-textured-area over-merging WL99/100 both flagged before.

**Final decision: adaptive support is REJECTED, not adopted.** Two independent findings point the same way (not material + real percolation regression on implementation), matching the directive's own stop conditions. Worklog 100 (`SUPPORT_MODE_FIXED_MASKED_KNN`) remains the only baseline; the adaptive module is kept in the repo as a diagnostic/experiment, not wired into any default path.

12 new focused tests, full regression 1170 passed 1 skipped (+12 from WL100's 1158). See [[project_bilateral_interface_region_merge]] and [[project_interface_coherent_region_merge]] for the preceding stages.
