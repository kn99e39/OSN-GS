**Two separate "volumetric dataset" efforts — do not confuse them.** [[project_volumetric_gaussian_scene_dataset]] (worklog 125, now `docs/worklogs/19_volumetric_gaussian_reliability_scene_dataset.md`) rebuilt `gaussian_reliability_scenes.py`/`surface_region_adversarial_scenes.py` — fixtures used ONLY by the isolated covariance-guided pipeline's own pytest suite (worklogs 113-124), never by the actual benchmark CLI. THIS memory is about a **different, later correction**: the user clarified that "synthetic dataset" should mean the one `osn-gs benchmark` (→ `nurbs_constructor_benchmark/runner.py`) actually loads, which is `scenes.py` + `ground_truth.py` + `metrics.py` (`SyntheticGaussianScene`, `SCENE_NAMES`) — a wholly separate, much more heavily-consumed module (~19 files: `boundary_first.py`, `boundary_first_support_runner.py`, `runner.py`, 4 devtools scripts, ~10 test files with exact-value assertions tied to old height-field geometry).

**What changed.** `SCENE_NAMES` was `("saddle_shell", "spherical_cap", "folded_roof", "wave_annulus")` — all still single height-fields `z=f(x,y)`, just with more dramatic curvature ("depth-bearing" was an earlier, incomplete attempt at 3D-ness). Replaced with genuine multi-face solids: `SCENE_NAMES = ("box", "cylinder", "sphere")`. The old 4 depth-bearing scenes were deleted entirely (code + oracle functions); the other 15 `LEGACY_SCENE_NAMES` (plane/sine/crease/triangle/u_shape/crescent/planar_hole/... ) were left **completely untouched** — they feed a different, older KDE/raster-based component/decomposition regression suite unrelated to `osn-gs benchmark`, and rewriting them was explicitly out of scope.

**Core architecture problem, chosen fix (user picked option 1: full 3D-native redesign, not an approximation or opt-out).** `ground_truth.py`/`metrics.py`'s hole/topology/support-domain metrics were built entirely around rasterizing a SINGLE shared `[-1,1]^2` XY plane — meaningless for a face oriented away from that view (a box's side wall projects to a line). Fix: added `GroundTruthFace` (own local `[-1,1]^2` domain + analytic `to_world`/`to_local` (inverse) + `normal_fn` + `support_predicate`) and a `SyntheticGaussianScene.faces: tuple[GroundTruthFace,...] | None` field. Every consuming function in `ground_truth.py`/`metrics.py` dispatches on `scene.faces is not None`; legacy height-field scenes (`faces=None`) use the 100%-unchanged old code path. For metrics specifically: `_combined_face_raster` concatenates each face's own local raster side-by-side (with a full-width gap to prevent cross-face flood-fill bridging), so all the EXISTING 2D hole/component/boundary helpers work unmodified on this face-aware combined raster instead of a single shared-view one.

**Oracle contract, made genuinely 3D**: `oracle(points) -> (residual, normal)` must work for ANY query point (not just points on the true surface) since `runner.py:score_state` scores RECONSTRUCTED patch samples against it. Implemented as exact closed-form SDFs: box = `max(abs(p)-h, 0).norm() + min(max_axis(abs(p)-h), 0)` with nearest-face-axis normal; cylinder = combined radial/axial SDF; sphere = trivial `|p|-r`. Verified: residual < 1.2e-7 on true-surface points, ≈0.05 on points offset by 0.05 along the normal, normal alignment = 1.0.

**Four real bugs found, all newly exposed by exact/uniform 3D geometry that height-field scenes never triggered:**
1. **`_tangent_frame_quaternion`'s trace-based quaternion extraction breaks down for 180°-class rotations** (trace ≈ -1): both qw and the qx/qy/qz numerators collapse toward 0 simultaneously, silently returning the identity quaternion for e.g. normal=(0,0,-1) instead of the correct rotation. Height-field scenes' normals were always small continuous perturbations around +z and never hit this. Fixed with the standard robust Shepperd's-method 4-branch extraction (branch on whichever of trace/m00/m11/m22 is largest). This is a **pre-existing bug in shared production-adjacent code**, not something introduced this round — worth remembering if quaternion-from-rotation-matrix conversions show up elsewhere.
2. **Random uniform per-face point sampling has too much local density variance**, silently fragmenting a single flat box face into ~25 spurious `same_surface` regions (same root-cause class as worklog 115's density-calibration bugs). Fixed by switching to jittered regular grids (`_grid_uv`).
3. **Cylinder side wall's circumference-vs-height physical aspect ratio mismatch** (4.4 vs 2.0 at radius=0.7,height=1.0) made a plain square grid anisotropically dense in one direction, still fragmenting. Fixed by scaling grid cell counts per axis to the true physical aspect ratio.
4. **Cylinder side seam duplication**: local u=-1 and u=+1 both map to the exact same physical angle (0 == 2π), so a naive inclusive linspace duplicates an entire ring of points — these showed up as dozens of tiny isolated 2-point regions disconnected from the main ring. Fixed by dropping the duplicated endpoint for periodic axes (`periodic_u=True` in `_grid_uv`).

After all four fixes: pairwise `same_surface` region count is exactly 6 (box), 3 (cylinder: side+2 caps), 1 (sphere) — matching true topology precisely.

**Disclosed, NOT-fixed finding — important, will resurface**: `osn-gs benchmark`'s DEFAULT constructor (`--constructor canonical`, the covariance-guided pipeline wired in by worklog 124/126 — now `docs/worklogs/18_canonical_visible_nurbs_training_integration.md`/`20_adc_synchronized_canonical_visible_nurbs_experiment.md`, fail-closed with no fallback) currently **hard-errors** on all three new scenes even though the underlying region-formation graph is perfectly correct (6/3/1 regions) — `RuntimeError: ... no materialized NURBS (state='review_required', regions=6, components=46)`. Root cause: the world-space boundary half-edge / ordered-loop / materialization stages (worklog 118-123, now `docs/worklogs/12_...md` through `17_...md`, built and owned by a different concurrent thread) have never been validated against a genuinely CLOSED multi-face solid — their own worklog 121 (now `docs/worklogs/15_gaussian_to_visible_nurbs_end_to_end_integration.md`) says explicitly "clean plane and curved sheet only." Fixing this is a separate, large task, out of scope for a dataset-replacement round. **`--constructor boundary_first` (the older KDE/raster comparator) DOES work end-to-end** for all three scenes with sensible metrics (accuracy_rms 0.01-0.02, correct gt_patch_count 6/3/1, face-aware support/topology metrics all populated) — this is the concrete evidence that the new dataset+ground-truth+metrics rewrite is itself correct; the gap is purely in the OTHER pipeline. Anyone running `osn-gs benchmark` with no arguments right now will hit this hard failure — mention `--constructor boundary_first` as the working alternative until the canonical path's closed-solid support catches up.
